# Phase 2 — Evidence-backed learner memory

## Objective and scope

After two independent quiz answers show the same unit mistake, the learner can open Settings after a restart, see exactly which attempts support the memory, and correct or forget it. The learner can also explicitly save, edit, and forget a learning goal or preference. The quiz and memory controls work offline. This phase stops at storage and management. Tutor retrieval, embeddings, model-assisted extraction, and the “Memories used” disclosure are later phases.

Use the existing single learner per `STUDY_DATA` directory and the server-assigned `local` owner. Share the memory setting and learner-wide records across English and Vietnamese. Keep automatic memories scoped to the originating roadmap. Begin capture only after opt-in and only from new quiz submissions. Phase 2 includes no historical import. Test replay and stale-work handling at the persistence boundary that future import and indexing will use.

The current grader returns a Boolean and the quiz route appends anonymous attempts to JSON progress. A dimension mismatch is evidence about units. An incorrect magnitude, choice, or unparseable answer is insufficient to infer its cause. Use distinct questions as the independence threshold so repeated submissions of one problem cannot promote a memory.

## Implementation tasks

Implement with an application-lifespan worker that attempts bounded batches at startup and periodically, independently of quiz latency. The routes are `GET/POST /api/memories`, `PATCH/DELETE /api/memories/{id}` (DELETE takes the expected `revision` query parameter), `PUT /api/memories/capture`, `GET /api/memories/{id}/evidence/{attempt_id}`, and `POST /api/memories/resume`. A learner edit makes that record learner-managed. Use the latest qualifying observation per topic, lesson version, and question index. One supporting question is tentative, two or more establish a recurring mistake, and zero resolves it.

- [x] **T1 — Add the memory repository and migration (R1, R2, R5, R6).** In `backend/main.py`, apply schema version 2 after the existing version 1 step in the same startup transaction. Add `backend/learner_memory.py` with owner-keyed storage for the capture setting, memory records, quiz evidence, pending events, and suppression. Store memory ID, kind, stable concept key, scope, language, statement, status, confidence, revision, and timestamps. Evidence records carry the source type, roadmap/topic/lesson version, question index, stable attempt ID, and known observation time. Pending events carry a unique source key, collection generation, expected memory revision when one exists, and retry state. Use a unique owner/source key and a unique owner/scope/concept key for automatic records. Run every lookup and mutation through the server-resolved owner. Keep suppression to stable non-text keys and ordering metadata. Record manual provenance for explicit memories.
- [x] **T2 — Capture idempotent quiz evidence (R2, R3, R4, R7).** In `backend/physics.py`, expose the deterministic diagnostic from the grading path while preserving `grade()`'s Boolean contract for its callers. Distinguish a missing unit from an explicitly written dimensionless unit. In `backend/main.py`, accept an optional UUID `attempt_id`, generate one when omitted, and add it to new progress entries. The reader retains its UUID while retrying the same submission and creates a new one after success or an answer change. Index the owner and UUID to the attempt's route, question, lesson version, and position so duplicates can be checked across routes against the original saved answer. Serialize the progress read, duplicate check, append, index write, and enabled enqueue in one SQLite transaction. Use the existing grade behavior for choice answers and malformed input. Carry only diagnostic and source identifiers in the queue. Recheck the setting inside the write transaction so a concurrent disable has a defined ordering.
- [x] **T3 — Fold attempts into evidence-backed status (R3, R4, R6).** Key diagnoses by missing versus incompatible units and canonical expected dimensionality. Order events by committed sequence and require separate question identities within the same roadmap. Use the most recent qualifying observation for each question. A later correct answer clears that question's supporting observation. Keep unclassified failures from creating evidence or clearing existing evidence. Save the projection and consume its event atomically, with deduplication and a fresh check of owner, capture generation, suppression, and current revision. A learner edit or forget takes precedence. Attempt bounded processing at startup and periodically in the application worker. Recoverable processor failures retain durable work and leave the quiz response successful. Keep queue diagnostics to identifiers, counts, and error categories.
- [x] **T4 — Add memory controls and source lookup (R2, R5, R6, R7).** Add `GET /api/memories`, `POST /api/memories`, `PATCH /api/memories/{id}`, `DELETE /api/memories/{id}`, and a capture-setting update under `/api/memories`. Return the current capture state and owner-scoped memory list, including evidence references and revision. Require expected revision on mutations of existing records. Return localized validation and stale-revision errors, and use the existing origin protection. Allow explicit goal and preference creation when capture is enabled. On disable, cancel queued capture and reset the collection generation so re-enabling starts with fresh pending work. Make one owner-scoped source lookup under the memory route that resolves an attached attempt against saved progress and the recorded lesson version, and reports a missing or changed source without substituting a newer answer. In the forget transaction, delete the memory and its derived evidence, cancel matching pending events, and write suppression. A revision-qualified active-record lookup must reject forgotten IDs. Let the learner explicitly resume collection for a forgotten pattern using an eligible post-forget attempt ID. Validate the attempt against current ownership, capture generation, lesson version, and diagnostic. Set a new capture cutoff and use the selected attempt as the first observation, so older evidence stays excluded and promotion still needs a second question.
- [x] **T5 — Add bilingual Settings UI (R2, R4, R5, R6, R7).** Extend `src/main.tsx` and `src/types.ts` with the memory view and quiz retry handling. Let the learner expand an evidence link to see the exact saved question, submitted answer, result, and date where known, including evidence recorded in the other language. Offer a remember action on eligible quiz feedback for a suppressed pattern while capture is enabled. Preserve learner-entered text in its original language. Render diagnostic labels through existing translations. Show conflicts and source-unavailable states, keep forms keyboard accessible, and leave the draft available after a failed save. Explain the distinction between pausing capture and forgetting a memory and what remains in study history.

## Exit check

With providers unavailable, two separate qualifying answers create one recurring unit mistake whose two sources can be opened after restart. One wrong answer remains tentative. A learner correction wins over pending work. Forgetting survives restart and replay, an old indexing revision cannot read the deleted record, and the learner can still inspect the original quiz history. Both language paths and legacy upgrades pass. The independent report and architecture document are saved before the roadmap is updated.
